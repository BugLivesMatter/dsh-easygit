# EasyGit — план развития: паритет с GitLens и дальше

Документ фиксирует, что уже работает, что добавлять в первую очередь и чем
EasyGit может быть сильнее GitLens. Проверка текущего состояния — скриптом
`scripts/verify-branches.mjs` на репозитории `easygit-playground`
(отчёт: `docs/branch-verification.md`).

## Уже есть в 0.1

- Граф коммитов: лейны, изогнутые рёбра мержей, стабильные цвета, чипы refs,
  отметка HEAD, бейджи задач и worktree.
- Дивергенция от интеграционной ветки: `↑N` / `↓N` относительно `main`
  (у локальной ветки обычно нет upstream, поэтому `ahead/behind` пустые).
- Ветки задач `easygit/task-<id>` + отдельный worktree на владельца + переезд
  рабочего каталога агента.
- Безопасные checkpoint'ы: только tracked-файлы автоматически, новые файлы —
  по явному списку, секретоподобные пути исключаются и показываются.
- Быстрый коммит, `Commit & Push`, `Push`, `Explain` (LLM по патчу).
- Автопоиск репозиториев внутри папки проекта, если сама папка не git.

## P0 — паритет с GitLens (1–2 итерации)

1. **Меню ветки**: rename, delete, merge в текущую, «создать от коммита»,
   «переключить в новом worktree».
2. **Diff по файлу в панели**: сейчас есть патч коммита целиком; нужен список
   файлов с раскрытием, подсветкой +/-, переход к строке.
3. **WIP-строка в графе**: незакоммиченные изменения как отдельный узел над
   HEAD, как working tree в GitLens, с кнопкой «закоммитить tracked».
4. **Stash**: save / apply / pop, обязательный checkpoint перед переключением
   ветки при грязном дереве.
5. **История файла**: `git log --follow -- <path>`, клик по файлу в Composer.
6. **Compare**: выбрать две ветки → список файлов и diff `base...head`.
7. **Upstream**: publish branch, set upstream, fetch, `pull --ff-only`.
8. **Undo**: `reset --soft` к коммиту и `revert`, всегда после checkpoint.
9. **Поиск по коммитам**: subject / автор / hash, фильтр по ветке и дате.
10. **Производительность**: виртуализация списка (сейчас лимит 300 строк) и
    ленивая загрузка патчей.

## P1 — сильнее GitLens

11. **Граф, знающий про задачи**: цепочка «задача → ветка → worktree → сессия
    агента», статус задачи прямо в графе, предупреждение при push незакрытой
    задачи.
12. **Конфликт-радар**: брать занятые файлы из `dsh-file-claim` и подсвечивать
    в Composer файлы, которые правит другой агент.
13. **Политика checkpoint'ов**: перед каждым сообщением агента, squash при
    merge задачи в интеграционную ветку.
14. **Explain шире**: сводка по диапазону коммитов, «что изменилось в ветке
    против main», черновик описания PR.
15. **PR через `gh`**: create / draft / review state / проверки CI — только по
    явному подтверждению и никогда без показа диффа.
16. **Уведомления**: статус PR и CI в шапке панели.
17. **Blame**: автор строк при наведении на файл.
18. **Realtime**: SSE вместо опроса раз в 5 секунд, чтобы граф совпадал у всех
    агентов и вкладок.

## P2 — дальше

19. Мультирепозиторный вид: все репозитории папки проекта на одном экране
    (обнаружение уже реализовано).
20. `cherry-pick`, `bisect`-помощник, интерактивный rebase с подтверждением.
21. Аватары/инициалы авторов, heatmap активности.
22. Дисковый кэш графа для больших репозиториев.

## Принципы безопасности

- Никогда `force push`.
- Никогда не коммитить секреты без явного разрешения пользователя.
- Перед разрушающим действием (switch, reset, merge, rebase) — checkpoint.
- UI и агентские инструменты вызывают одно и то же ядро: поведение не
  расходится.

## Что мерить

- Время до первого кадра графа на репозитории с 5 000 коммитов.
- Число ручных шагов на путь «задача → коммит → push → PR».
- Доля коммитов, сделанных без участия человека (авто-checkpoint + задача).
